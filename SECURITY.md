# Security Policy

## Supported versions

Security fixes are applied to the latest published version. Older extension packages are not supported.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature from the repository **Security** tab after the repository is public. Do not open a public issue for an unpatched vulnerability.

Include the affected version, supported site, reproduction steps, impact, and any suggested mitigation. Use synthetic data and remove credentials, private conversations, authenticated media URLs, and captured audio.

The maintainer will acknowledge a complete report, investigate it, and coordinate disclosure after a fix is available. No bounty program is currently offered.

## Scope

Useful reports include unintended audio capture, credential exposure, permission bypasses, unsafe transcript rendering, arbitrary provider endpoints, cross-tab request confusion, and release-package contamination.

Provider availability, quota limits, upstream model behavior, and unsupported changes to Messenger or Instagram markup are bugs rather than security vulnerabilities unless they create a concrete security impact.
